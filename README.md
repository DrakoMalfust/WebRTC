## 📖 О проекте

Простой, но полноценный чат, где сообщения летят **напрямую** между браузерами через **WebRTC DataChannel**. Сервер нужен только для «знакомства» пользователей (signaling) и как fallback, если P2P не удалось установить.

Такой подход даёт:
- ⚡ **Минимальную задержку** — сообщения не проходят через сервер
- 🔒 **Конфиденциальность** — трафик шифруется DTLS поверх P2P
- 🧩 **Простое развёртывание** — сервер на 50 строк кода

## 🏗️ Архитектура

```
┌──────────┐         ┌──────────────────┐         ┌──────────┐
│ Клиент A │ ◄─────► │ Signaling Server │ ◄─────► │ Клиент B │
└────┬─────┘         │   (Node.js+ws)   │         └─────┬────┘
     │               └──────────────────┘               │
     │        offer / answer / ICE (только знакомство)   │
     │                                                  │
     └────────────── WebRTC DataChannel ────────────────┘
                  Прямое P2P-соединение
                    (сообщения чата)
```

**Как это работает:**
1. Оба клиента подключаются к WebSocket-серверу и получают уникальные ID.
2. Клиент A создаёт `RTCPeerConnection` и отправляет `offer` через сервер.
3. Клиент B отвечает `answer`, стороны обмениваются ICE-кандидатами.
4. Устанавливается DataChannel — сообщения идут напрямую.
5. Если P2P не поднялся (строгий NAT) — сообщения уходят через сервер (relay).

## 🚀 Быстрый старт

### Требования
- **Node.js** 18+
- Современный браузер (Chrome, Firefox, Safari, Edge)

### Установка

```bash
git clone https://github.com/your-username/webrtc-chat.git
cd webrtc-chat
npm install
```

### Запуск

```bash
node server.js
```

Открой в браузере: **http://localhost:8080**

### Тестирование

1. Открой `http://localhost:8080` в первой вкладке — увидишь свой ID.
2. Открой ту же ссылку во второй вкладке — там будет **другой** ID.
3. Скопируй ID из первой вкладки, вставь во вторую, нажми **Соединиться**.
4. После статуса «P2P соединение установлено» пиши сообщения — они идут напрямую.

> 💡 **Совет:** для теста с другого устройства в той же Wi-Fi сети используй `http://<локальный-IP>:8080`. Учти, что WebRTC требует secure context — для внешних сетей понадобится HTTPS.

## 🛠️ Технологии

- **Node.js** + **`ws`** — signaling-сервер
- **WebRTC** (`RTCPeerConnection`, `RTCDataChannel`) — P2P
- **WebSocket API** — обмен сигналами
- **ES Modules** — современный синтаксис на клиенте и сервере
- **STUN** (`stun.l.google.com`) — обнаружение публичного IP

## ⚠️ Известные ограничения

- **Без TURN** соединение не всегда устанавливается через строгий NAT (мобильный интернет, корпоративные сети).
- **Перезагрузка страницы** рвёт P2P — нужно подключаться заново.
- **Нет аутентификации** — это учебный проект, не для продакшена.
- **STUN от Google** — публичный, может быть недоступен в некоторых регионах.
